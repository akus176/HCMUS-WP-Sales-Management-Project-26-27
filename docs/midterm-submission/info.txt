Coffee Shop Management System
Midterm feature summary

1. Project scope

The midterm version is a Windows WinUI coffee shop management client.
It uses PostgreSQL for persistent data.
The client uses a restricted local database account at runtime.

2. Completed features

Catalog and menu:

- Create and manage categories.
- Create and manage menu items.
- Configure sizes, add-ons, and recipes.
- Deactivate an item and exclude it from new orders.

Customers and orders:

- Create and update customer profiles.
- Store delivery addresses.
- Track loyalty history.
- Create dine-in, takeaway, and delivery orders.
- Support discount approval, payment, cancellation, and fulfillment workflows.

Inventory and reports:

- Manage ingredients and suppliers.
- Create and post purchase receipts.
- Apply stock adjustments with a reason.
- View stock movements and low-stock items.
- View revenue, best-seller, order-channel, and low-stock reports.

3. Midterm demo data

The repeatable seed includes:

- 20 products.
- 5 categories.
- 12 customers.
- 24 baseline orders.
- Ingredients, suppliers, operators, and delivery staff required by the demo.

4. High-effort work completed

- Transactional order confirmation and cancellation.
- Stock and loyalty compensation during order changes.
- PostgreSQL migrations and repeatable seed data.
- Restricted runtime database role.
- Automated domain, application, database, and WinUI tests.
- Responsive six-workspace desktop UI.

6. Known limitations

- The midterm client connects to PostgreSQL directly.
- The final version will move the client to the typed API.
- Final staff authentication and server-side role authorization are not complete.
- Card and e-wallet tenders are simulated.
- Staff selection in the midterm client is not final authentication.
- Optional business-data AI integration is planned for the final version.

7. Submission files

- `repo.txt` contains the repository URL.
- `youtube.txt` contains the unlisted demo URL.
- `instructions.txt` explains how to run the project.
- `info.txt` describes the implemented scope and limitations.
- `pat.txt` is a private, read-only token file. It must stay outside Git and be added
