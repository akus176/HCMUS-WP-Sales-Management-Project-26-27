# Best-seller reporting

`BestSellerReportQueryHandler.GetBestSellersAsync` returns independently ranked menu-item and size-variant lists for inclusive local business dates. Supply the business time zone, `BestSellerSort.Quantity` or `BestSellerSort.Revenue`, and a positive limit (default 10 per list). Dates use the same inclusive-start, exclusive-end UTC boundaries and validation as revenue reports.

Quantity counts each line once on its order's completion date, including fully discounted or zero-price orders. Revenue follows `RevenueRecognitionRule`: only successful payments on fully paid, completed orders, capped at the payable total after approved ordinary and loyalty discounts. Cancelled orders, orders with cancellation timestamps, and inventory-restored orders contribute neither quantity nor revenue. Pending/failed payments and payments after completion do not qualify.

Each recognized payment is allocated proportionally to immutable line totals, including add-ons. Shares round down to cents; remaining cents go to the largest fractional remainders, with ascending line ID resolving ties. Allocation happens per payment before aggregation, so adjacent date ranges reconcile with a combined range. Quantity and revenue can occur in different reporting periods: an order paid in September and completed in October contributes September revenue and October quantity.

Item and variant IDs identify groups. When a catalog reference is null, its snapshot name identifies the corresponding group. Names and sizes are read from the latest contributing order snapshot (completion time, then ascending order and line IDs), so current catalog edits, prices, and deactivation cannot rewrite history. Quantities and revenues include all sizes in item rankings; variant rankings keep each size separate. Add-ons contribute value to the drink, not extra sold drinks.

Rankings sort descending by the selected metric, then the other metric, then ordinal item/size snapshot names and ascending item/variant IDs. Ranks are sequential, and the limit applies after aggregation to each list. When the limit includes all groups, item and variant lists each reconcile with the revenue report; a limited list represents only its displayed sellers. Empty periods return empty lists.

Verification: application tests cover rankings, ties, limits, historical snapshots, discounts/add-ons, cent allocation, split dates, eligibility, free orders, and validation. `BestSellerReportIntegrationTests` uses the same migrated PostgreSQL fixture as revenue and channel reports, including inactive renamed catalog data and null catalog references. Set `COFFEESHOP_TEST_POSTGRES` to a disposable PostgreSQL server where the test user can create/drop databases; CI runs these tests against PostgreSQL 18.
