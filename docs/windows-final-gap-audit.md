# Windows final architecture and shared API gap audit (#148)

Baseline: `main` at `60109ffeca8ff858e16f3e1bf35f7199e552f996`, inspected on 2026-11-02. This is an evidence review of the seven OpenSpec tasks mapped by [issue #148](https://github.com/akus176/HCMUS-WP-Sales-Management-Project-26-27/issues/148), not a claim that final API behavior works. Status means **implemented** only when code and the task's required verification are present; **partial** means some relevant code exists; **missing** means the required path is absent; **unverified** means code exists but required runtime evidence is unavailable. The [mobile baseline](mobile-delivery-baseline.md) independently probed the current API and should be used alongside this audit.

The identity [spec](../openspec/changes/build-coffee-shop-management-system/specs/identity-and-access/spec.md) requires a successful/denied login, revocable sessions, permission checks, final-admin protection and security audits. Its six-role API behavior has no current HTTP verification. The current `PosOperatorSession` selects a local operator; it does not establish an authenticated API principal. The Windows API migration depends on an actual protected server contract, so its final release proof cannot be inferred from the midterm UI tests.

The CI workflow provides a Windows build/test job and a PostgreSQL infrastructure test job. These are useful midterm signals; they do not run a clean Docker API startup, API/database readiness, authorization matrix, final WinUI dependency check, or final traffic trace. Keep OpenSpec tasks 9.1, 9.2, 10.1, 10.5, 11.1, 11.7 and 13.1 unchecked until their full implementation and verification pass.
